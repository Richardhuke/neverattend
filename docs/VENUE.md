# 考勤地点（身体素质课）

## 结论

| 项 | 值 |
| --- | --- |
| 地点 | 浙江大学紫金港校区 **西田径场（左跑道）西侧中点** |
| 纬度 | `30.3074` |
| 经度 | `120.0765` |
| 圈内验证 | 2026-11-12 17:23 App 弹出「您已进入考勤范围内,是否立即签到?」 |
| 抖动 | 默认 ±8 m（`NA_JITTER`），保证仍落在圈内 |

这个点已经写进代码默认值，页面打开就是它，不需要每次重填：

- `deploy/adb-ns.mjs` → `CONFIG.mock` 默认 `'30.3074,120.0765'`（可用 `NA_MOCK` 覆盖）
- `frontend/src/pages/queue.vue` → 排队页纬度/经度初值
- `frontend/src/pages/index.vue` → Run 页「远程签到（设备队列）」初值 + `geo` 兜底
- `backend/src/config.js` → `geo.venue`（`VENUE_LAT` / `VENUE_LNG` 可覆盖）

## 现场怎么确认的（2026-11-12 第 8 次课）

1. 老师在 App 里发布考勤后，地图上出现**红色小圆圈**（考勤半径），我方箭头在圈外，点签到弹「不在考勤范围内」。
2. 由于本机 `curl` 出网被封（OSM / Overpass / Nominatim 全失败），无法反查经纬度，改为「设 mock 坐标 → 截图 → 读地图 POI」逐步逼近。
3. 关键一步是**标定比例尺**：同一张截图里缩放级别未知，像素不能直接换算。做法是移动两次已知位移，看同一 POI 在图上走了多少像素：
   - Δlat +0.0027（≈300 m）→ 425 px ⇒ 0.71 m/px
   - Δlng −0.0019（≈183 m）→ 235 px ⇒ 0.78 m/px
   - 两次接近，取 0.72 m/px
4. 用 0.72 m/px 换算箭头到圈心的像素偏移（dx −75 / dy −113）⇒ 西 54 m、北 81 m ⇒ `30.3074,120.0765`。
5. 设为该坐标后立刻弹「您已进入考勤范围内」，确认进圈。

## 别的课次怎么办

圈心由老师每场发布，可能小幅变化。稳妥流程：

1. 进「课程排课」→ 当天课次「签到」→ 等红圈出现。
2. 用本坐标先试一次；若提示「不在考勤范围内」，按上法用两次位移重新标定（`tools/sweep.mjs` 可批量试点）。
3. 圈内后点大圆钮 → 「确定」。

## 备注

- 模拟定位走系统 test provider（`cmd location providers add-test-provider gps` + `set-test-provider-location`），**不需要开发者选项、不需要第三方 Fake GPS**。
- 2026-11-12 实测：App 与服务器都接受该坐标，未出现任何 mock 风控提示；`dumpsys location` 可见 `WorkSource{10389 net.crigh.mysport}` 正在消费 mock 数据。
- 签到成功后重复点大圆钮不会重复记，服务端会拒绝重复签到（表现为页面来回跳「不在范围内」）。
